# Geometry contract

This document defines the first shared contract for the original terrain core. It applies to generated mesh data, preview input, and STL output.

## Coordinate system

- Mesh coordinates are in **millimeters**.
- X increases east/right; Y increases north/up on the map; Z increases upward.
- The printable base is the plane `z = 0`.
- The terrain surface is at or above the configured base thickness.
- The mesh uses right-handed coordinates and outward-facing triangle winding. Positive signed volume is required.

## Height field input

The terrain builder accepts a rectangular, row-major grid of finite surface-relief values in millimeters. It normalizes the lowest sampled value to the configured base thickness:

`surfaceZ = baseThicknessMm + (sampleMm - minimumSampleMm)`

When geographic DEMs are connected, `sampleMm` will be generated by the single geographic-to-local transformation using the project formula:

`(elevationM - documentedDatumM) × horizontalModelScale × verticalExaggeration`

The current core deliberately does not project geographic coordinates or fetch DEMs. That keeps deterministic topology tests offline and prevents synthetic data from becoming a production fallback.

## Solid rules

The builder creates top surface triangles, a flat bottom, and four closed perimeter walls in one indexed mesh. Before export it must reject meshes with non-finite vertices, degenerate triangles, boundary edges, non-manifold edges, or non-positive signed volume.

## Reference boundary

TrailPrint-3D was inspected for behavior only: it uses an OpenTopography-backed DEM height field and checks mesh closure. No TrailPrint-3D code, assets, mesh data, or defaults are used in this implementation. OpenTopography suitability, terms, coverage, credentials, and request limits remain a separate pending provider decision.
